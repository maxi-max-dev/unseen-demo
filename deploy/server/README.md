# 把照片处理搬到服务器上

## 为什么要这么做

宾客传照片上来之后，得有个程序判断「这张是朝哪个方向拍的、该放回空间哪个位置」。

**这个程序必须一直开着，照片才会被处理。**

现在它只有人手动开终端敲命令才会跑。婚礼当天如果忘了开，或者那台 Mac 断电断网，会发生的事情是：

- 宾客扫码传照片，**手机显示上传成功** ✅
- 但大屏上什么都不会出现，**也不会报错**
- 宾客只会觉得「这东西坏了」

代码里的注释原话就是「现场当场懵」。

搬到服务器上之后：程序挂了自动重启、服务器重启也会自己回来、Mac 关机完全不影响。

---

## 分工：Mac 干什么，服务器干什么

**婚礼之前，在 Mac 上做**
- 摄影师的全景图上传、建空间、跑深度模型（这一步重，但只做一次，做完就不用了）
- 做完把空间数据传给服务器（一条命令）

**婚礼当天，服务器上跑**
- 盯着 OSS 收件箱，宾客一传照片就处理、归位、发布
- 全自动，没人需要盯着

**为什么深度模型不搬**：它只在建空间时跑一次，婚礼当天根本不用。搬过去要多花好几倍的机器钱（模型 1.46GB、要更大内存），不划算。

---

## 买什么机器

**实测数据**（在 Mac 上量的，不是估的）：

| 项目 | 实测 |
|---|---|
| 内存占用 | **425 MB** |
| 处理一张照片 | **17 毫秒** |
| 要不要 GPU | **不要** |

所以**最便宜的入门机器就够了**，不需要几百块一个月的 GPU 服务器。

**建议配置**

- **地域：杭州（cn-hangzhou）** ← 这条最重要
  你的照片存在阿里云杭州的 OSS。服务器买在同一个地方，两边走内网：**流量免费、延迟极低**。买在别的地方要付跨网流量费，还慢。
- **配置：2 核 2G，40G 系统盘**（内存实际只用 425MB，2G 是留足余量）
- **系统：Ubuntu 22.04 或 24.04**（安装脚本也支持 CentOS/Alibaba Cloud Linux）
- **带宽**：按量付费最小档即可，照片走内网不占公网带宽

按当前阿里云入门款价位，这类配置大约**几十块钱一个月**。⚠️ 具体价格我没查实时报价，你下单时以控制台为准。

## 🔐 先说安全这一条

现在那份 OSS 凭证（`~/.config/psm/aliyun.json`）大概率是**主账号的钥匙**——拿到它等于拿到你整个阿里云账号。

放到一台开在公网上的服务器上，风险就跟着上去了。

**建议先做这一步**（在阿里云控制台，大概五分钟）：

1. 访问控制 RAM → 创建一个子用户，勾「编程访问」
2. 给它单独授权：**只能读写 `psm-advx-2026` 这一个 Bucket**，别的什么都不给
3. 拿这个子用户的新钥匙，写一份新的 `aliyun.json` 给服务器用

这样万一服务器被人搞了，对方最多能动这一个 Bucket，动不了你账号里别的东西。

**这一步我没法替你做**（要登你的阿里云控制台）。嫌麻烦也可以先用现在的钥匙跑通，但**收钱之前一定要换成子账号**。

## 怎么装

**① 在服务器上装**

登上服务器，跑：

```bash
curl -fsSL https://raw.githubusercontent.com/maxi-max-dev/unseen-demo/main/deploy/server/setup.sh | bash
```

或者先把代码拉下来再跑 `bash deploy/server/setup.sh`。

它会装 Python 和依赖、预下载 CLIP 模型、把服务注册成开机自启。**预下载这步很重要**：不然婚礼当天现下 580MB 模型，够你紧张的。

**② 放凭证**（在 Mac 上跑，IP 换成真的）

```bash
ssh root@<服务器IP> "mkdir -p /root/.config/psm && chmod 700 /root/.config/psm"
```

```bash
scp ~/.config/psm/aliyun.json root@<服务器IP>:/root/.config/psm/
```

**③ 婚礼前，把空间传过去**（在 Mac 上跑）

```bash
bash deploy/server/sync-space.sh s4 <服务器IP>
```

会自动核对两边文件数，对不上就报错不让你往下走。

**④ 启动**（在服务器上跑，`s4` 换成真的空间 ID）

```bash
systemctl enable --now unseen-worker@s4
```

**⑤ 看它在干什么**

```bash
journalctl -u unseen-worker@s4 -f
```

婚礼结束想停：

```bash
systemctl disable --now unseen-worker@s4
```

## 婚礼前一天，建议实测一次

**别把第一次运行留到婚礼当天。**

1. 用一个测试空间跑一遍上面全部步骤
2. 自己用手机扫码传一张照片
3. 看 `journalctl` 里有没有正常处理，看展页面上照片有没有出现
4. **然后故意把服务杀掉**（`systemctl stop unseen-worker@测试空间`），确认 systemd 会自动拉起来

第 4 步是关键：**没测过的自动重启，等于没有自动重启。**

## 还没解决的（老实说）

- **服务器挂了没人会通知你**。worker 死了 systemd 会拉起来，但整台服务器要是没了（欠费、被封、机房故障），你不会收到任何消息。这个洞要补的话是另一件事。
- **空间数据是单向的**：Mac → 服务器。如果在服务器上产生了新数据（宾客照片的归位结果），Mac 上那份就是旧的了。目前 OSS 上的是最新的，Mac 那份只当建空间用。别在婚礼中途从 Mac 再传一次覆盖回去。
- **这套没在真服务器上跑过**。脚本是照着代码实际需求写的、参数都对过，但真机验证要等你买了机器。
