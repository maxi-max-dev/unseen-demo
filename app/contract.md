# 一个「空间」里到底有什么

写给下一个接手的人（也写给将来那个小程序）：一个空间的数据长什么样，字段叫什么，
每个字段是谁写的、谁读的。**字段名全部来自现在真在跑的代码**，没有一个是编的：
观景那套读 `tour.js` 里的 `window.TOUR`，宾客页读 OSS 上的 `space.json`（示例见
`web/join.html` 里的 `MOCK_SPACE`，`?mock=1` 跑的就是它）。

两套结构目前**不是同一份 JSON**，共用的概念是「空间 → 全景节点 → 照片（带方向）」。
下面按这三层写，末尾列出两套之间的对应关系。文中标注：
📖 = 页面只读它，✍️ = 后台工人写它。

---

## 一、空间（最外面那一层）

### 云版 `space.json`（宾客页 / 展览页读的那份）

| 字段 | 长什么样 | 干什么用 |
|---|---|---|
| `schema` | `"psm-space/1"` | 版本号，字符串。将来结构变了靠它分叉 📖 |
| `id` | `"s-mock"` | 空间 id。宾客页从链接 `?s=<id>` 拿到它，再去拼 `space.json` 的地址 📖 |
| `title` | `"陈屹 ♥ 林沐 · 2026.7.26"` | 整个空间的标题，页头和分享卡用 📖 |
| `couple` | `"陈屹 & 林沐"` | 这场的主角名字 📖 |
| `published` | `true` | 没发布的空间宾客页不给看 📖 |
| `collection` | `{ status: "open" \| "closed" }` | 还收不收照片。`closed` = 停止收集 📖 |
| `capacity` | `{ maxPhotos, received, remaining, full }` | 名额。四个都可以缺，缺了页面自己算：`received` 缺就用 `photos` 的条数，`remaining` 缺就用 `max - received` 📖 |
| `limits` | `{ maxPhotos }` | `capacity.maxPhotos` 的老写法，两个都读，`capacity` 优先 📖 |
| `upload` | 见下 | 直传 OSS 的策略。也认 `post` / `direct` 两个别名，三个里有一个就算能传 📖 |
| `nodes` | 数组，见第二节 | 这个空间有哪几个全景点 📖 |
| `photos` | 数组，见第三节 | 已经挂进空间的照片（服务端认了的）📖 |
| `pending` | 数组，同 `photos` 结构 | 还在处理 / 等人看一眼的照片。页面把它和 `photos` 并起来用 📖 |
| `tasks` | 数组，见第四节 | 任务墙上的「缺这个角度」和「心愿」📖 |
| `contributors` | `[{ name, photos, points }]` | 贡献榜。只统计已入选的照片，待审的人一行都没有 📖 |

`upload` 里面（一段 OSS 直传策略，公开页面里放着是安全的，因为里面没有密钥，
策略本身限死了前缀、大小和有效期）：

```
upload: {
  host:            "https://<bucket>.oss-cn-hangzhou.aliyuncs.com",
  OSSAccessKeyId:  "...",
  policy:          "...",        // base64 策略
  signature:       "...",
  keyPrefix:       "spaces/<空间id>/inbox/",
  maxSize:         12582912      // 字节
}
```

### 本地版 `window.TOUR`（`tour.js`，观景页读的那份）

| 字段 | 长什么样 | 干什么用 |
|---|---|---|
| `meta` | `{ title, version }` | 标题 + 结构版本号 📖 |
| `journey` | `true` | 真时按 `nodes` 的顺序推「下一站」，做成一条动线 📖 |
| `map` | `{ image, width, height }` | 平面导览图（一张图 + 它的像素尺寸）📖 |
| `geoRoute` | `[[lng, lat], …]` | 婚车路线的途经点，高德 GCJ-02 坐标 📖 |
| `nodes` | 数组，见第二节 | 全景节点 📖 |
| `links` | `[{ from, to, yaw }]` | 节点之间的走法：从 `from` 这个节点，朝 `yaw` 这个方向，走到 `to` 📖 |

## 二、全景节点（空间里的一个「地方」）

`nodes` 里一条 = 现场的一个位置，挂着一张全景图和一批照片。

| 字段 | 云版 | 本地版 | 说明 |
|---|---|---|---|
| `id` | ✅ `"n1"` | ✅ `"jieqin"` | 节点 id，任务和照片都靠它认地方 |
| `name` | ✅ `"宴会厅"` | ✅ `"新娘家"` | 给人看的名字 |
| `time` | ✅ `"18:00"` | ✅ `"09:08"` | 现场时间，字符串不是时间戳 |
| `panorama` | ✅ `"nodes/n1/pano.jpg"` | ✅ `"assets/panos/jieqin.jpg"` | 那张全景图，相对路径 |
| `sub` | — | ✅ `"新娘家 · 堵门红包"` | 副标题 |
| `chapter` | — | ✅ `"接亲"` | 属于哪一幕 |
| `map` | — | ✅ `{ x: 0.13, y: 0.8 }` | 在导览图上的位置，**0-1 的比例**不是像素 |
| `geo` | — | ✅ `{ lng, lat }` | 真实经纬度，高德 GCJ-02 |
| `photos` | — | ✅ 数组 | 本地版把照片挂在节点里；云版是平铺在空间的 `photos`，靠 `nodeId` 认节点 |

---

## 三、一张照片

这是整个系统的核心那一条：**一张照片 + 它当时朝着的方向**。

### 云版 `photos[]` / `pending[]`

| 字段 | 长什么样 | 谁写的 | 说明 |
|---|---|---|---|
| `id` | `"p1"` | ✍️ | 照片 id |
| `src` | `"photos/p1.jpg"` | ✍️ | 大图路径 |
| `thumb` | `"thumbs/p1.jpg"` | ✍️ | 缩略图，列表里用这个 |
| `nodeId` | `"n1"` | ✍️ | 属于哪个全景节点 |
| **`yaw`** | `105.6` | ✍️ | **方向，0-360 度。** 这一条就是产品那句「让照片回到它当时朝着的方向」。系统只定到 30 度一格、一圈 12 格，照片钉在扇区正中间，所以「误差半格」是结构上必然的。没算出来时是 `null`，页面必须能处理 `null`（文案走「AI 正在定位照片方向…」，不许瞎报一个角度） |
| **`confidence`** | `0.9158` | ✍️ | **匹配度，0-1。** 这张照片和全景对上的把握 |
| `margin` | `0.1019` | ✍️ | 辨识度：第一名和第二名的差距。光有 confidence 不够，两个方向都像的时候 margin 会很小 |
| **`state`** | `"auto_ok"` | ✍️ | **这张照片现在什么处境**，取值见下表 |
| `reason` | `"匹配度 0.92、辨识度 0.102，两项都达标，自动入选"` | ✍️ | 大白话解释为什么是这个 state，直接显示给宾客看 |
| **`contributor`** | `"小雨"` | ✍️ | **谁传的**（宾客自己填的昵称，可以不填） |
| `taskId` | `"t4"` 或 `null` | ✍️ | 补的是哪个任务，`null` = 自由上传不对任何任务 |

`state` 的取值（页面里真在分支的那几个）：

| 值 | 意思 | 宾客看到 |
|---|---|---|
| `auto_ok` | 两项都达标，自动入选 | 已经放进空间 |
| `approved` | 主办方看过，人工放进来的 | 已经放进空间 |
| `uploaded` | 传到了，还没算出方向 | AI 正在定位照片方向… |
| `needs_review` | 算出来了但不够有把握，等主办方确认 | 方位等主办方确认（**这一档按隐私红线不带 yaw**） |
| `quota_full` | 到达时名额已经收满 | 投稿到达时名额已经收满 |
| `quarantined` | 自检环判断这张不像这个场地，自动隔离 | 「这张看着不像这个场地，先放一边了」 |
| `rejected` | 主办方看过，这次没有选入 | 「主办方这次没有选入」 |
| `scene_updated` | 传完之后场景或任务被改了，这张对不上了 | 「场景或任务刚刚更新了，请回到任务墙重新选择」 |

只有 `auto_ok` 和 `approved` 算进贡献榜。这条口径不能改回去：以前传完立刻报「拿到 +20 分」，
可 `needs_review` 的人根本不上榜，报出去的分是编的。

（以上 8 个值全部来自 `web/join.html` 的 `stateLabel()` / `settleRow()` / `photoState()` 三处真在跑的分支，
一个没编。`aiStateFor()` 把它们收敛成 4 档 AI 卡片配色：success / review / processing / error。）

### 本地版 `nodes[].photos[]`

| 字段 | 长什么样 | 说明 |
|---|---|---|
| `src` | `"assets/photos/w001.jpg"` | 图片路径。本地版没有单独的 `id`，`src` 就是它的身份 |
| **`yaw`** | `51` | 方向，0-360 度，同上 |
| `pitch` | `7` | 俯仰角，度。云版目前不产出这个 |
| **`confidence`** | `1.0` | 0-1。实测这批合成素材落在 0.793 - 1.0 |
| **`by`** | `"manual"` 或 `"auto"` | **谁定的方向**：`manual` = 人工标的，`auto` = 算出来的。注意这跟云版的 `contributor`（谁传的照片）不是一回事，本地版没有「谁传的」这个概念 |
| `caption` | `"堵门红包"` | 一句说明，可以没有 |

## 四、任务（任务墙上那些卡）

`tasks[]`，只有云版有。

| 字段 | 长什么样 | 说明 |
|---|---|---|
| `id` | `"t1"` | 任务 id |
| `nodeId` | `"n1"` | 哪个节点缺照片 |
| `type` | `"gap"` 或 `"wish"` | `gap` = 系统发现这个方向没人拍；`wish` = 新人自己许的愿 |
| `title` | `"缺这个角度"` / `"我想要一张我妈妈笑的照片"` | 卡片标题 |
| `brief` | `"站在舞台右前方，回头拍向主桌那一片"` | 人话说明怎么拍 |
| **`yaw`** | `210` 或 `null` | 要补的方向。`wish` 型是 `null`（心愿本来就不认方位） |
| `yawRange` | `[190, 240]` 或 `null` | 可接受的方向区间 |
| `briefImage` | `null` | 示意图，暂时都是 null |
| `bounty` | `50` | 悬赏分 |
| `status` | `"open"` / `"filled"` | 还缺 / 已经有人补上了 |
| `filledBy` | `["小雨"]` | 谁补的 |
| `createdBy` | `"system"` / `"couple"` | 系统发现的，还是新人许的 |

`gate.state`（页面自己算出来的整场状态，不是 JSON 字段，写在这里免得下一个人重新推）：
`open` 能传 / `preparing` 主办方还没上全景 / `full` 收满了 / `closed` 停止收集。

## 五、两套之间怎么对应

| 概念 | 云版 `space.json` | 本地版 `window.TOUR` |
|---|---|---|
| 空间标题 | `title` | `meta.title` |
| 版本 | `schema` | `meta.version` |
| 节点 | `nodes[]` | `nodes[]`（字段更多） |
| 照片挂在哪 | 空间级 `photos[]` + `nodeId` | 节点级 `nodes[].photos[]` |
| 照片身份 | `id` | `src` |
| 方向 | `yaw` | `yaw` |
| 把握 | `confidence` + `margin` | `confidence` |
| 谁传的 | `contributor` | 没有（只有 `by` = 方向是人标的还是算的） |
| 处境 | `state` | 没有（本地版都是已定稿的） |
| 节点之间怎么走 | 没有 | `links[]` |
| 地图 | 没有 | `map` + `nodes[].map` + `geo` + `geoRoute` |

**给小程序的一句话**：要照片能回到它当时朝着的方向，最少需要
`空间 id` + `nodes[].panorama` + 每张照片的 `yaw`。
`confidence` / `margin` / `state` / `reason` 决定这张照片该不该出现、以及怎么跟宾客解释，
`contributor` 决定署名。剩下的都是锦上添花。
